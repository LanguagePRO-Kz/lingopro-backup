# Чертёж: Плановый движок (маршрут + раскладка)

**Статус:** подход на утверждение (код не написан) · **Дата:** 08.07.2026
**Архитектура из RECON-2 §3 (утверждена): AI строит МАРШРУТ (редко, дёшево), код раскладывает ДНИ (ежедневно, бесплатно).** Этот документ доводит её до реализуемости.

Опирается на существующее: `daily-plan.ts` (генерация дня, стрик, DailyTask, `daily_progress`/`task_results`), `topic_mastery` (двусторонний: ошибки ↓ / успехи ↑), реестр тем, голосовые уроки с mode+focus (`/api/voice/session`), адаптер (`route_plan` → Sonnet), `profiles.study_minutes_daily` (Диагностика v2 §6), поля D-блока (`target_level`, `exam_date`, `exam_date_mode`, `exam_horizon_months`).

---

## 1. Две сущности

**Маршрут (route)** — недельная структура тем до цели. Генерирует AI, хранится, версионируется.
**День (day plan)** — конкретные задачи на дату. Считает чистая функция, нигде не хранится заранее (только выполненное — в `daily_progress`, как сейчас).

## 2. Маршрут: модель данных

Хранение: `profiles.study_route jsonb` (миграция 0003; отдельная таблица не нужна — история версий не продукт-требование, храним одну актуальную + `route_history` НЕ делаем).

```ts
export type StudyRoute = {
  version: 1;
  generatedAt: string;            // ISO
  model: string;                  // кто сгенерировал (аудит)
  inputs: {                       // снапшот входов — для «маршрут устарел?»
    level: Level; targetLevel: "B2" | "C1";
    examDate?: string; horizonMonths?: number; minutesDaily: number;
    weakTopics: string[];         // strength<60 на момент генерации
  };
  weeks: RouteWeek[];             // 4..16
};
export type RouteWeek = {
  index: number;                  // 1-based
  theme: Localized;               // «Падежи и пространство» — мотивационный заголовок
  topics: string[];               // 2–4 id из реестра — фокус недели
  skillsEmphasis: Partial<Record<Skill, number>>; // веса 0..1, сумма ~1
  mockPolicy: "none" | "section" | "full";        // §5
  milestone?: Localized;          // «мок ≥ 45/100»
};
```

## 3. Генерация маршрута (AI, task `route_plan` → Sonnet)

**Когда вызывается** (все триггеры → один серверный эндпоинт `POST /api/ai/route`):
1. Первый заход на дашборд после диагностики (нет `study_route`).
2. Изменение в настройках: `minutesDaily`, `targetLevel`, `examDate/mode` — с подтверждением (см. §6).
3. Кнопка «пересобрать план» при большом расхождении (мок ниже вехи на ≥15 баллов) — предлагает UI, решает студент.
4. НЕ вызывается по расписанию: недельная адаптация — детерминированная (§4), AI-регенерация только по событиям. Rate-limit: фича `route` в limits.ts — 3/день, 10/мес.

**Промпт** (`src/lib/ai/prompts/route-plan.ts`, системный — кэшируется):
- Роль: методист TÖMER. Вход (user msg): уровень, цель, дата/горизонт, минуты/день, слабые темы (id+strength), список ВСЕХ тем реестра с уровнями (enum!), пороги 60/75.
- Методология в промпте: порядок тем «от опор к надстройке» (падежи → времена → залоги → придаточные), интерливинг навыков, слабые темы — в первые 2 недели И повторно через 3–4 недели, последние 25% недель — mock-heavy, темы уровня выше цели не включать.
- Выход: СТРОГО JSON `{weeks: [...]}` (schema в промпте). Темы — только из enum.
- **Валидация** (`validateRoute()`): темы ⊆ реестра, недель = `clamp(ceil(daysLeft/7), 4, 16)` (без даты: horizonMonths×4.3; «не знаю» → 12), веса навыков нормализуются, mockPolicy расписание из §5 накладывается поверх (AI может предлагать, код гарантирует).
- **Детерминированный fallback** (`fallbackRoute()`): если AI недоступен/невалиден — шаблонный маршрут: темы реестра уровня студента → цели по порядку файла, слабые вперёд, равные веса. Продукт работает без AI-ключа — честно, просто менее персонально.
- Стоимость: ~$0.03–0.05 за генерацию (промпт-кэш), редкие вызовы.

## 4. Раскладка дня (чистый код) — `src/lib/plan/layout.ts`

Заменяет `specsFor()` из daily-plan.ts. Сигнатура:

```ts
buildDay(input: {
  route: StudyRoute; date: string; dayNumber: number;
  mastery: MasteryRow[];          // strength, last_error_at, last_practiced_at
  history: DayRow[];              // 30 дней
  minutesDaily: number; locale: Locale;
}): DailyTask[]
```

**Алгоритм (бюджет = minutesDaily, заполняем приоритетами):**
1. **Повторения (spaced):** темы с `strength<60` и `last_error_at` старше интервала (1→3→7→14 дней от числа ошибок; интервал = `[1,3,7,14][min(3, error_count-1)]`) → grammar/vocab задача по теме (task-content уже умеет банки по навыку; фильтр по теме — новый параметр, см. §7 п.5). Максимум 2 повторения/день.
2. **Голосовой урок** — 3 раза в неделю при minutes≥30 (dayNumber%7 ∈ {1,3,5}), 2 при 15: `DailyTask{ skill:"speaking", kind:"voice_lesson", mode: <из недельного цикла: bolum1→bolum2→bolum3>, focusTopics: неделя.topics ∩ слабые ∪ первые }`, estimatedMinutes: 10 (= дневная база минут!). Ссылка: `/dashboard/speaking/live?mode=X&focus=a,b,c` — live-страница читает query, передаёт в `/api/voice/session`, сервер валидирует focus ⊆ реестр и использует вместо автофокуса.
3. **Темы недели:** задачи по `week.topics` с весами `skillsEmphasis` (grammar/reading/listening/writing из существующих банков).
4. **Мок по расписанию** (§5): вместо 2–3 обычных задач.
5. Добивка до бюджета vocabulary/reading. Каждой задаче — `estimatedMinutes` из констант (сейчас в specsFor), сумма в пределах `minutesDaily ± 10%`.

`DailyTask` расширение (обратно-совместимое): `kind?: "regular" | "voice_lesson" | "mock_section" | "mock_full"`, `focusTopics?: string[]`, `mockSection?: "dinleme"|"okuma"|"yazma"|"konusma"`. localStorage-ключ плана → `v4` (isPlanValid уже отбрасывает старые схемы).

**Определение «текущей недели маршрута»:** `weekIndex = clamp(ceil(dayNumber/7), 1, weeks.length)` — где dayNumber уже считается от `takenAt` (существующий `dayNumberFrom`). При регенерации маршрута dayNumber НЕ сбрасывается: новый маршрут строится «отсюда до цели», недели заново с 1, а `routeStartedAt` пишется в route.inputs (добавить поле) — weekIndex считать от него.

## 5. Доля моков растёт к дате

Код накладывает поверх маршрута (не доверяем AI):
```
daysLeft > 60 или дата неизвестна: 1 секционный мок / нед (неделя.mockPolicy="section")
30 < daysLeft ≤ 60: 2 секционных/нед
14 < daysLeft ≤ 30: 2 секционных + 1 полный/нед
daysLeft ≤ 14: через день полный/секционный, обычные задачи только повторения слабых тем
```
Секционный мок = существующий ExamRunner на одну секцию (формат уже чинится в Content-чертеже); полный — 4 секции, Konuşma = голосовая сессия mode `full`. Результаты — в `mock_results` (таблица есть) → вехи маршрута.

## 6. Смена темпа/цели/даты: пересчёт с ЧЕСТНЫМИ последствиями

**Модель осуществимости** (`feasibility.ts`, чистая функция — юнит-тесты):
```
topicMinutes = 90            // констант: минут практики на «закрытие» темы (калибруем по факту)
remainingTopics = темы маршрута с strength<60 (или не пройденные недели × topics)
practiceShare = 0.7          // доля минут дня, идущая в темы (остальное — моки/повторения)
daysNeeded = ceil(remainingTopics × topicMinutes / (minutesDaily × practiceShare))
verdict: ok        если daysNeeded ≤ daysLeft × 0.85
         tight     если ≤ daysLeft
         notEnough иначе → deltas: minutesNeeded = ceil(remainingTopics×topicMinutes/(daysLeft×practiceShare))
                            или dateNeeded = today + daysNeeded
```
**UX при изменении настроек (никаких молчаливых перестроек):** модалка-подтверждение:
- ok: «При 45 мин/день успеваешь к 15.09 с запасом. Пересобрать план?» [Да/Отмена]
- notEnough: «При 30 мин/день к 15.09 успеешь ~70% маршрута. Варианты: (а) 50 мин/день, (б) дата 05.10, (в) цель B2 вместо C1» — три кнопки + «оставить как есть» (честно позволяем, план помечается бейджем «напряжённый»).
Подтверждение → `POST /api/ai/route` (регенерация) → новый план дня немедленно (паттерн уже реализован в фиксе интенсивности: перестроить сегодня, сохранить зачтённое).

## 8. Риски

| Риск | Митигация |
|---|---|
| AI-маршрут невалиден/бессмыслен | жёсткая схема + validateRoute + fallbackRoute; маршрут виден на /plan — студент и основатель могут глазами проверить |
| «Дрожание» плана (каждый чих — новый план) | регенерация только по явным событиям с подтверждением; needsRegen сравнивает inputs; выполненное всегда сохраняет зачёт |
| topicMinutes=90 — грубая константа | честно помечено «оценка»; после 2–3 недель реальных данных (`task_results.created_at` уже пишется) пересчитать из фактического темпа |
| Банки задач не тегированы темами | v1: недельные темы влияют на grammar/vocab через уровень+ротацию, а точечно — через повторения и голосовые фокусы (те тегированы); тегирование банков — следующая итерация, зафиксировать TODO |
| Konuşma-мок требует минут голоса | полный мок расходует голосовую квоту — честно предупреждать перед стартом; секционные моки Konuşma не чаще 1/нед |

**Приёмка:** (1) юнит-тесты layout (бюджет соблюдён ±10%, повторения приоритетнее, мок-расписание по daysLeft) и feasibility (три вердикта на граничных входах); (2) e2e-сценарий: диагностика → маршрут сгенерён → день содержит урок с фокусом из недели 1 → смена минут 45→15 показывает честную модалку с вариантами; (3) без AI-ключа продукт строит fallback-маршрут.

# Часть 1. Диагностика: почему неточна и как сделать честной

## 1.1 Диагноз текущей версии (файл `src/lib/quiz.ts`)

| Проблема | Где | Следствие |
|---|---|---|
| Speaking оценивается по **числу слов и секунд** (`scoreSpeakingAnswer`, `scoreSpeakingDuration`) | quiz.ts | Список покупок, надиктованный 40 секунд, получает высокий балл. Навык не измеряется вообще |
| Writing оценивается по **длине, пунктуации и наличию турецких букв** (`scoreWriting`) | quiz.ts | Бессвязный текст с «ç» и запятыми обгоняет короткий грамотный |
| **Аудирования нет** | — | Dinleme — 25 из 100 баллов реального TÖMER — не измеряется |
| ~5 вопросов на модуль | quiz.ts | Шаг одной ошибки ±20% → точность уровня не лучше «±1 уровень» |
| Разбор — статический `ANALYSIS`, один на всех | quiz.ts | «Ты знаешь X / пробел Y» не связаны с ответами — фейк |
| `predictedScore = 40 + overall × 0.55` | quiz.ts | Выдуманная формула, не привязанная к шкале TÖMER |
| По-вопросные ответы **не сохраняются** (`QuizResult` хранит только проценты модулей) | quiz.ts | Честный разбор и карта пробелов невозможны по данным |

## 1.2 Якорь: официальный формат TÖMER (подтверждено источниками)

- 4 секции — **Dinleme, Okuma, Yazma, Konuşma — по 25 баллов, итог /100**.
- Пороги сертификата: **≥60 → B2, ≥75 → C1** (Sakarya TÖMER; аналогично YEE TYS). Сертификат действует 2 года.
- Yazma: выбор 1 темы из 3, 45 минут, письменное выражение мысли.
- Konuşma: 2 части — karşılıklı konuşma (диалог) и sözlü anlatım (монолог).

Эти пороги — готовая продуктовая механика: прогноз диагностики и мок-экзаменов выражаем как «балл /100 + вероятность порога B2 (60) / C1 (75)», а не выдуманный «predictedScore».

## 1.3 Целевая архитектура диагностики (v1, реализуемо в P0)

**Принцип: закрытые задания — детерминированный скоринг (бесплатно), открытые — AI (единственный честный способ).**

1. **Реестр тем** (`topics` — единый справочник ~50 грамматических/лексических тем A1–C1: гармония гласных, локатив/датив, аккузатив, изафет, времена -DI/-mIş/-Iyor/аорист, причастия -An/-DIK, условные, пассив, послелоги, коллокации…). Каждое задание банка тегируется `{level, topic}`. Реестр — общий для диагностики, фидбека, плана и mastery: это позвоночник всего ядра.
2. **Okuma + Dinleme (закрытые):** двухступенчатый адаптив — роутинг-блок 6 заданий (A2–B1) → по результату уточняющий блок 8–10 заданий на границе уровня. 14–16 заданий на навык вместо 5 → шаг ошибки ~6–7% вместо 20%. Скоринг детерминированный, стоимость $0.
   - **Аудио для Dinleme:** до получения официальных материалов — генерим один раз через ElevenLabs TTS по нашим текстам заданий, храним статикой (`public/audio/…`). Честный синтетический звук (это норма даже для реальных экзаменов-тренажёров), единоразовая стоимость — копейки.
3. **Yazma (открытое):** 1 короткое задание по уровню роутинга (60–100 слов). Оценка через AI-адаптер: рубрика TÖMER Yazma (задание/содержание, связность, грамматика, лексика) → балл /25 + список ошибок с тегами тем. Structured output со схемой — темы только из реестра (enum), связка гарантирована. ~$0.02/проверка.
4. **Konuşma:** на запуске честно — **«оценим на первой голосовой сессии»**: первая сессия с голосовым преподавателем (блок C) начинается с 2-минутного плейсмента, результат дописывается в диагностику. Это (а) честно, (б) активация главной платной фичи. Вариант v1.1 — запись 60–90 с → Scribe STT → AI-анализ текста (~$0.03), добавим после запуска голоса.
5. **Выход диагностики (QuizResult v2):** уровень CEFR, per-skill /25, прогноз /100 **интервалом** (например «52–61»), вероятности порогов B2/C1, карта пробелов из конкретных тем («путает локатив -DA и датив -A при глаголах движения»), и — критично — **сохранённые по-вопросные ответы** (`answers[]` с тегами) для честного разбора и старта mastery.

**Нужен ли AI:** для закрытых — нет. Для Yazma (и позже Konuşma) — да: никакая эвристика не отличит грамотный текст от бессвязного. Модель — та же, что победит в bake-off (часть 2).

**Стоимость одной диагностики: ~$0.02–0.05** (одна AI-проверка Yazma + синтез итогового разбора). При 1 000 диагностик/мес — $20–50/мес. Приемлемо; диагностика бесплатная для юзера и остаётся дешёвой для нас.

# Часть 2. Фидбек: ошибка → тема → правило → исправление + память

## 2.1 Схема данных (ляжет в миграцию 0002)

```
errors (evidence):  каждая найденная ошибка из ЛЮБОЙ активности
  {user_id, source: writing|tutor|voice|mock|diagnostic, quote, correction,
   rule, explanation, topic_id → topics, severity, created_at}

topic_mastery:      агрегат силы по теме (механика speak.com)
  {user_id, topic_id, strength 0–100, success_count, error_count,
   last_error_at, last_practiced_at}
```

- **Обновление strength — детерминированное** (EWMA: успех +, ошибка −, вес свежих событий выше). Никакого AI в пересчёте — предсказуемо и бесплатно.
- **Возврат к ошибкам:** слабые темы (strength &lt; 60) попадают в план с интервалами повторения 1 → 3 → 7 → 14 дней; тема «закрыта» после 3 успехов подряд при strength &gt; 80, но остаётся в редких повторениях.
- **Гарантия связки «ошибка→тема»:** в structured-output-схеме ответа AI поле `topic_id` — enum из реестра. Модель физически не может вернуть тему вне справочника.
- Формат ошибки везде одинаков: **цитата → исправление → правило (названо) → объяснение на языке интерфейса**. Практика на турецком, объяснения на RU/EN/TR/KK.
- **Для KK-юзеров (утверждено 07.07.2026):** схема ошибки получает опциональное поле `kk_parallel` — параллель с казахской грамматикой, где она есть («ырықсыз етіс = edilgen çatı», «тәуелдік жалғауы = iyelik eki»). Заполняется только при `feedback_lang=kk` и только для тем с прямым соответствием (флаг в реестре тем). Маркетинговый угол: «түрік тілін қазақ тілі арқылы үйрен».

### Живой bake-off (проведён 07.07.2026)

- **Набор:** 5 эссе (A2→C1) с **29 заранее заложенными типизированными ошибками** (реестр в Приложении A): гармония гласных, локатив/датив, аккузатив, изафет, -DI/-mIş, причастия, пассив, условные, управление глаголов, отрицательное согласование, кальки с русского («sınavı verdim»). 2 помечены как minor/стилистические — проверка на переспам. Плюс 3 крайних случая: пустой ввод, русский текст вместо турецкого, вставленный текст самого задания.
- **Участники:** Claude Sonnet 4.6, Claude Opus 4.8 (тот же ключ — заодно закрываем вопрос «Sonnet vs Opus»), DeepSeek V4. Идентичный промпт и схема ответа (Приложение B).
- **Метрики:** recall заложенных ошибок (отдельно — критических), precision (ложные срабатывания), корректность названного правила, качество объяснения на русском, поведение на edge-cases, целостность JSON, латентность, цена.
- **Пороги приёмки для основной модели:** recall критических ошибок ≥ 80%, ложных срабатываний &lt; 15%, объяснения — правило, а не «так не говорят».
- Участники по факту: Claude Sonnet 4.6, Claude Opus 4.8, DeepSeek V4 Flash, **DeepSeek V4 Pro** (обнаружен в API, добавлен четвёртым). Явные ID моделей, без депрекируемого алиаса `deepseek-chat`.
- Тех-заметка: первый прогон показал, что думающим моделям мало `max_tokens: 4000` (Sonnet и DS-Pro тратили бюджет на размышления и обрезали JSON) — перегнано с 16 000. Это дефект тестового скрипта, в зачёт моделям не шёл.

- Sonnet дорог из-за адаптивных размышлений (~4.1K токенов выхода); с отключённым мышлением для этой задачи цена ≈ $0.025, латентность упадёт.

Вопрос основателя: справятся ли модели с грамотными объяснениями на казахском (аудитория KK). Доп-прогон: Sonnet 4.6, Opus 4.8, DS V4 Pro × эссе 1 и 4 (13 закладок), `feedback_lang=kk`.

| | Sonnet 4.6 | Opus 4.8 | DS V4 Pro |
|---|---|---|---|
| Recall закладок | 13/13 | 13/13 | 13/13 |
| Объяснения на казахском (с ә/ғ/қ/ң/ө/ұ/ү/і) | 13/13 | 13/13 | 15/15 |
| Терминология | верная («тәуелдік жалғауы», «изафет») | **лучшая** — родные термины («ырықсыз етіс» для пассива) | верная, но местами расплывчато («етіс түрі» без уточнения какой) + rule по-английски |
| Лишние находки | 0 | 0 | 2 (обе minor, спорные пере-исправления: «o doktor → o bir doktor») |

Выводы:
- **Казахский фидбек работоспособен у всех трёх.** Бонус для KK-аудитории: казахский — тюркский язык, грамматические концепты совпадают с турецкими 1:1 (тәуелдік жалғауы = тот же притяжательный аффикс, ырықсыз етіс = edilgen çatı, септіктер = падежи) — объяснения ложатся на родную грамматику ученика без «перевода понятий». Это продуктовое преимущество, стоит подсветить в маркетинге на KK.
- Точность формулировок на казахском у Claude чуть выше (Opus — эталон терминологии), у DS-Pro — хорошо, но с редкой расплывчатостью и лёгкой склонностью пере-исправлять.
- **Решение в адаптер: per-language маршрутизация** (карта в конфиге): RU/EN → DS V4 Pro (дёшево, проверено), **KK → Claude Sonnet 4.6** (максимальная гарантия качества формулировок). Цена вопроса мала: Writing ≤3/день. Финальное слово — за основателем-носителем по живым примерам.
- В продакшн-промпт: требовать язык интерфейса для **всех** полей (`rule`, `advice`), не только `explanation`.

### Вердикт (к утверждению основателем)

- **Writing-проверки и разбор диагностики: DeepSeek V4 Pro** — единственный со 100% recall реальных критических ошибок, 100% русских объяснений, чистыми edge-cases, при цене **в ~17 раз ниже** Sonnet ($0.0038 против $0.064). Латентность ~50 с приемлема для асинхронной проверки эссе (UI показывает прогресс).
- **Тьютор, голосовой разбор, генерация маршрута: Claude Sonnet 4.6** — живой диалог требует быстрого стриминга и качества рассуждения; там DS-Pro с его латентностью не подходит.
- **Страховка в адаптере:** ответ DS валидируется схемой; при мусоре/таймауте — автоматический ретрай на Sonnet (fallback одной строкой конфига). Смена основной модели — одна env-переменная, как и требовалось.
- Честная оговорка: выборка 5 эссе × 1 промпт — достаточна для выбора, но финальная приёмка B1 всё равно идёт на расширенном наборе (10 эссе + edge-cases), как и планировалось.
- Стоимость всего прогона (41 вызов, 4 модели) — меньше $1.5.

# Часть 3. План, который ведёт к сдаче

## 3.1 Решение: AI задаёт структуру, код раскладывает по дням (гибрид)

**Сравнение вариантов:**

| | AI генерит план каждый день | Чистый детерминизм | **Гибрид (рекомендация)** |
|---|---|---|---|
| Цена/юзер/мес | ~$1+ только на план | $0 | ~$0.07–0.13 |
| Предсказуемость/тестируемость | низкая (дрейф, галлюцинации дат) | полная | полная (раскладка — чистая функция) |
| Персонализация маршрута | высокая | слабая (комбинаторика уровень×цель×дата×пробелы в if-ах) | высокая |
| Латентность утром | секунды ожидания | мгновенно | мгновенно |

**Как работает гибрид:**

1. **Маршрут (AI, один раз после диагностики, ~$0.03–0.05):** вход — уровень, цель B2/C1, дата/горизонт экзамена, карта пробелов, интенсивность. Выход — structured JSON: упорядоченная последовательность тем из реестра с вехами («к неделе 4 — закрыты падежи, мок ≥ 45/100») и распределением по навыкам с учётом порогов TÖMER (до B2 нужно 60 — тянем отстающие секции, а не полируем сильные). Методология CEFR/TÖMER зашита в системный промпт (дескрипторы уровней, рубрики секций, принципы: spaced repetition, интерливинг навыков, доля мок-экзаменов ближе к дате) — промпт кэшируется (Anthropic prompt caching, чтение 0.1× цены).
2. **Раскладка по дням (код, $0, ежедневно):** расширение существующего `lib/daily-plan.ts` — чистая функция `(маршрут, exam_date/horizon, intensity, topic_mastery, история) → задачи дня`. Слабые темы возвращаются интервалами 1/3/7/14 дней; задачи берутся из банков по тегам тем.
3. **Адаптация (AI, по событию/раз в неделю, ~$0.01–0.02):** триггеры — тема провалена/закрыта, мок сильно разошёлся с прогнозом, дата экзамена изменена, план отстаёт от вех. AI корректирует маршрут (не дни!), код перераскладывает. Между триггерами лёгкая адаптация (перестановка ближайших тем по mastery) — тоже кодом, бесплатно.

Это и есть «предсказуемость + экономия токенов»: юзер каждый день мгновенно видит план, AI вызывается только там, где реально думает.

## 3.2 Карта дорогих вызовов и оптимизация

Telefonlarımızda **çok zaman geçiriyoruz için** ailemize ve arkadaşlarımıza daha az vakit ayırıyoruz. **Teknolojinin gelişme** çok hızlı ve bazen ona yetişmek zor. **Eğer teknoloji olmasa, hayatımız çok zor olacak** çünkü artık her şeyi internetten yapıyoruz: alışveriş, bankacılık, eğitim.

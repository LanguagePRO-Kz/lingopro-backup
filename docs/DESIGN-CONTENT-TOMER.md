# Чертёж: Контент TÖMER — формат, легальность, пайплайн

**Статус:** подход на утверждение · **Дата:** 08.07.2026
**Задача:** строить тренировочный контент в СТРОГОМ формате экзамена, не нарушая ничьих прав, с архитектурой, в которую позже «вставляются» официальные материалы (если основатель получит права) без переписывания логики.

---

## 1. Отчёт: что известно о формате из открытых источников

Проверено веб-исследованием 06–07.07.2026 (ссылки — в RECON-2 «Источники»):

| Факт | Источник | Надёжность |
|---|---|---|
| 4 секции: Dinleme, Okuma, Yazma, Konuşma — по 25 баллов, итог /100 | Sakarya TÖMER (объявления о Yeterlik Sınavı), SDÜ TÖMER (опубликованный образец) | Высокая — первоисточники университетов |
| Пороги: ≥60 → сертификат B2, ≥75 → C1; сертификат действует 2 года | Sakarya TÖMER | Высокая |
| Yazma: выбор 1 темы из 3, 45 минут | Sakarya TÖMER | Высокая |
| Konuşma: 2 части — karşılıklı konuşma (диалог) и sözlü anlatım (монолог) | Sakarya TÖMER | Высокая |
| Dinleme/Okuma: çoktan seçmeli (MC) | SDÜ образец | Высокая |
| Точное число вопросов и хронометраж секций | — | **НЕ подтверждено**: у разных центров (Ankara Ü. TÖMER, Sakarya, SDÜ, Yunus Emre TYS) варьируется |

Важная правда: «TÖMER» — не один централизованный экзамен, а семейство Türkçe Yeterlik Sınavı разных университетских центров + государственный TYS (Yunus Emre Enstitüsü). Общее ядро — 4 навыка × 25 и пороги. **Продуктовое решение: фиксируем собственный «LingoPRO exam blueprint» (§3) на этом ядре и честно называем тренажёр «в формате TÖMER/TYS», не «копией экзамена N».** Когда основатель принесёт официальные требования конкретного центра — blueprint правится числами в одном файле.

## 2. Легальность (практические правила, не юр.заключение)

1. **Формат/структура экзамена не охраняются** авторским правом (идеи, методы, структура — вне охраны). Строить оригинальные задания «в формате» — законно; так работают все издатели подготовительных материалов.
2. **Реальные варианты прошлых лет — охраняемые тексты.** Никогда не копируем задания/тексты/аудио из PDF-ов, «слитых» вариантов, чужих учебников. В том числе «с изменениями» — переписанный чужой текст остаётся производной работой.
3. **Товарный знак:** «TÖMER» принадлежит университетам (прежде всего Ankara Üniversitesi). Описательное использование («подготовка к экзаменам формата TÖMER») — нормальная практика; позиционирование «официальный TÖMER-тест» — нельзя. (Надпись «официальный партнёр» на лендинге — осознанное решение основателя, зафиксировано; к контенту не относится.)
4. **Официальные материалы в будущем** — только по письменному соглашению с центром; архитектура §5 позволяет подключить их отдельными JSON-файлами с `source: "official-<center>"` и ограничением доступа, ничего не переписывая.
5. Образец SDÜ — публично опубликованный университетом пример: используем его как **референс формата** (структуры, типов заданий), не копируя содержимое.

## 3. LingoPRO exam blueprint v1 (наш стандарт полного мока)

Числа выбраны консервативно по общему ядру; меняются в одном месте (`content/tomer/blueprint.json`):

| Секция | Заданий | Материалов | Время | Скоринг |
|---|---|---|---|---|
| Dinleme | 20 MC | 4 аудио (2 диалога, 2 монолога), каждое слушается 2 раза | 30 мин | 20 → /25 линейно |
| Okuma | 25 MC | 5 текстов (200–350 слов) | 45 мин | 25 → /25 |
| Yazma | 1 эссе (выбор 1 из 3 тем) | — | 45 мин | AI-рубрика /25 (готовый writing_review) |
| Konuşma | 2 части (диалог + монолог) | голосовая сессия mode `full` | ~12 мин | criteria/5 → /25 (готовый voice_review) |

Итог /100, вердикт: `<60 — сертификат не выдан · 60–74 — B2 · ≥75 — C1`. Грамматика как отдельная секция ИСКЛЮЧАЕТСЯ из моков (нарушение формата в текущем `mock-exams.ts`) — грамматический банк переезжает в тренажёр/дневной план.

## 4. Пайплайн авторинга оригинального контента

**Роли:** драфт — AI (Sonnet), контроль — нейтив/преподаватель (основатель организует), сборка — скрипт.

1. **Драфт.** Промпт-генератор (`scripts/draft-exam-content.mjs`, использует адаптер): на вход blueprint + уровень + список тем реестра для покрытия; на выход JSON-черновик секции. Требования в промпте: оригинальный текст (никаких пересказов известных статей), нейтральные темы (быт, город, образование, технологии, культура — без политики/религии), дистракторы правдоподобны и ровно один верный ответ, каждое задание тегируется темой реестра, где применимо.
2. **Нейтив-ревью (обязателен, чек-лист в docs/CONTENT-FORMAT.md):** естественность языка; единственность правильного ответа; уровень соответствует CEFR (порог: слова вне топ-N частотности для уровня); культурная нейтральность; отсутствие «знакомых» текстов (ревьюер подтверждает, что не узнаёт источник).
3. **Аудио:** `scripts/generate-exam-audio.mjs` — ElevenLabs TTS, диалоги двумя голосами (Ahu/Fatih/Gökçe), скорость 1.0, → `public/audio/tomer/<examId>/<itemId>.mp3`. В JSON — транскрипт (для проверки и доступности).
4. **Валидация сборки:** `scripts/validate-exam.mjs` — схема §5, счётчики blueprint, у каждого MC ровно один answer, аудиофайлы существуют, темы ⊆ реестра. CI-шаг (или ручной прогон) перед коммитом контента.
5. **Как основателю готовить материалы** (если пишет сам/с преподавателем): таблица-шаблон (Google Sheets колонки: section, level, topic, prompt, options A–D, answer, text_ref/audio_script) → конвертер `scripts/import-exam-sheet.mjs` (CSV → JSON). Формат таблицы описать в CONTENT-FORMAT.md — это его «интерфейс сдачи материалов».

Объём одного полного мока: 45 MC + 4 аудиосценария + 5 текстов + 3 темы эссе. Реалистичная цель v1: **2 полных мока + секционные банки** (секционные моки плана могут тянуть подмножества), дальше +1 мок/меяц.

## 5. Архитектура хранения и кода

```
content/tomer/blueprint.json          — числа §3
content/tomer/exams/lp-001.json       — полный мок (schema ниже)
public/audio/tomer/lp-001/*.mp3
docs/CONTENT-FORMAT.md                — спека схемы + чек-листы + шаблон таблицы
src/lib/tomer/types.ts                — типы схемы
src/lib/tomer/loader.ts               — load+validate (динамический import JSON)
scripts/{draft,validate,import,generate-audio}-*.mjs
```

Schema `exams/<id>.json` (сокращённо; полная — в CONTENT-FORMAT.md при реализации):
```jsonc
{
  "id": "lp-001", "version": 1, "source": "original",
  "targetLevels": ["B1","B2"], "title": {"ru":"…","en":"…","tr":"…","kk":"…"},
  "dinleme": { "timeLimitMin": 30, "audios": [
    { "id":"d1", "kind":"dialog", "src":"/audio/tomer/lp-001/d1.mp3", "transcript":"…",
      "questions": [ { "id":"d1q1", "topic":"other", "prompt":"…", "options":["…"], "answer":0 } ] } ] },
  "okuma":  { "timeLimitMin": 45, "texts": [ { "id":"t1", "title":"…", "body":"…",
      "questions": [ …как выше… ] } ] },
  "yazma":  { "timeLimitMin": 45, "prompts": [ {"id":"y1","prompt":"…","hint":{…}}, ×3 ] },
  "konusma":{ "mode": "full" }   // делегат в голосовую сессию
}
```

**Интеграция (файлы):**

| # | Файл | Что | Объём |
|---|---|---|---|
| 1 | types.ts + loader.ts + blueprint.json + CONTENT-FORMAT.md | фундамент схемы | M |
| 2 | `src/app/dashboard/mock/page.tsx` + ExamRunner | читать JSON-моки вместо `buildExam()`-ротаций; секции по blueprint; таймеры секций; скоринг /25; грамматику убрать | L |
| 3 | `src/data/mock-exams.ts` | выпилить после переезда (банки MC переиспользовать как сырьё для тренажёра) | S |
| 4 | Konuşma-секция мока | кнопка → live-сессия mode `full`; по завершении `mock_results.section_scores.konusma` из voice-report | M |
| 5 | `mock_results` персист + XP (E3) | итог /100 + вердикт B2/C1; история в стате | M |
| 6 | Контент lp-001, lp-002 | пайплайн §4 | L (контент) |

## 6. Риски

| Риск | Митигация |
|---|---|
| Несоответствие числам конкретного центра, куда пойдёт студент | blueprint.json — числа в одном месте; в UI честная строка «формат основан на опубликованных примерах университетских TÖMER; точный регламент уточняй в своём центре» |
| AI-драфт «протекает» знакомыми текстами | ревью-чеклист п.2; промпт требует оригинальные сюжеты; тексты прогоняются поиском по фразам (ручная проверка 2–3 фраз в Google) |
| Один верный ответ на самом деле не один | validate-скрипт не поймает семантику — ловит только нейтив-ревью; в проде — кнопка «ошибка в вопросе?» (лог в contact_messages, дешёво) |
| Konuşma-мок тратит голосовые минуты | предупреждение до старта; в блюпринте konusma-часть ~12 мин ≈ дневная база + 2 — честно показать |

**Приёмка:** lp-001 проходится целиком (4 секции, таймеры, /100, вердикт), валидатор ловит подсунутые ошибки схемы (тест с битым JSON), нейтив-ревью подписан на оба мока, «формат»-строка в UI на 4 языках.

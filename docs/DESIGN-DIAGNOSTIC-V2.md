# Чертёж: Диагностика v2

**Статус:** подход на утверждение (код не написан) · **Дата:** 08.07.2026
**Цель:** диагностика, которая (1) честно меряет уровень по 4 навыкам TÖMER + даёт балл /100 с порогами 60=B2/75=C1, (2) выдаёт карту пробелов по темам реестра, (3) наполняет `topic_mastery` для уроков и планового движка, (4) собирает параметры плана (цель, дата — блок D; минуты в день — здесь).

Всё ниже опирается на УЖЕ существующее: реестр тем [src/lib/ai/topics.ts](../src/lib/ai/topics.ts) (43 темы с уровнями), таблицы `error_events`/`topic_mastery` (миграция 0002 §7), сев [src/lib/ai/diagnostic-seed.ts](../src/lib/ai/diagnostic-seed.ts), AI-адаптер (`writing_review`/`diagnostic_analysis` → DS-V4-Pro, KK→Sonnet), `AnswerRecord` в [src/lib/quiz.ts](../src/lib/quiz.ts), голосовой плейсмент = первая сессия (агент готов).

## 1. Структура прохождения (25–30 мин, этапы)

```
Онбординг (существующий + 1 новый шаг)
  └─ шаг «минут в день» (см. §6)
Этап R — Роутер (5–7 мин): 10–12 адаптивных вопросов dil bilgisi + kelime
  └─ выход: рабочий уровень L ∈ {A1..C1} + первые точки карты тем
Этап S — Навыковые блоки на уровне L (полученном из R):
  ├─ Dinleme (5–6 мин): 8 вопросов (2 аудио)      → /25
  ├─ Okuma  (6–7 мин): 8–10 вопросов (2 текста)   → /25
  └─ Yazma  (7 мин): 1 задание по уровню, AI-оценка → /25
Konuşma → «оценим на первом живом уроке» (см. §7) → /25 (pending)
Результат: уровень + /100 (3 секции + pending) + карта пробелов + сев mastery
```

Роутер не показывается как «грамматика» в результатах TÖMER-вида — он служебный: калибрует уровень и размечает темы. Его точность per-topic — главный источник карты пробелов.

## 2. Банк заданий: формат и объём

Новый файл `src/data/diagnostic-bank.ts` (вынести банк из quiz.ts):

```ts
export type BankItem = {
  id: string;                  // "r-b1-014" (этап-уровень-номер)
  stage: "router" | "dinleme" | "okuma";
  level: "A1" | "A2" | "B1" | "B2" | "C1";
  topic: string;               // ОБЯЗАТЕЛЬНО, id из topics.ts (для dinleme/okuma допустим "other")
  prompt: string;              // турецкий
  hint?: Localized;            // как сейчас (скрыт для tr-локали)
  options: string[] | Record<Locale, string[]>;
  answer: number;
  // только для dinleme:
  audio?: { src: string; transcript: string };   // "/audio/diagnostic/d-b1-02.mp3"
  // только для okuma: ссылка на текст
  textId?: string;
};
export type BankText = { id: string; level: Level; title: string; body: string };
```

**Минимальный объём банка v2** (оригинальный контент, авторинг — см. DESIGN-CONTENT-TOMER §4):

| Этап | На уровень | Уровней | Итого |
|---|---|---|---|
| Роутер | 6 (по 1–2 на ключевые темы уровня) | 5 (A1–C1) | 30 |
| Dinleme | 8 вопросов = 2 аудио × 4 | 3 (A2/B1/B2) | 24 вопроса, 6 аудио |
| Okuma | 10 вопросов = 2 текста × 5 | 3 (A2/B1/B2) | 30 вопросов, 6 текстов |
| Yazma promptlar | 2 варианта | 4 (A2–C1) | 8 |
| **Всего** | | | **~92 вопроса + 6 аудио + 6 текстов + 8 промптов** |

Правило тегирования: у КАЖДОГО вопроса роутера — конкретная тема (не "other"); dinleme/okuma допускают "other" (навык понимания, не грамматика), но где вопрос проверяет конструкцию — тегировать. Ретейк: внутри (stage, level) вопросы выбираются детерминированной ротацией `seed = user_id hash + retake_count` — повторное прохождение даёт другие вопросы.

**Аудио Dinleme:** генерится один раз скриптом `scripts/generate-diagnostic-audio.mjs` (по образцу scratchpad/voice-test.sh): текст диалога → ElevenLabs TTS (два голоса из наших: Ahu + Fatih для диалогов), `eleven_multilingual_v2`, скорость 1.0 (экзаменационный реализм) → `public/audio/diagnostic/*.mp3` (~100–200 КБ каждый). Транскрипт хранится в банке (для дебага и будущего режима «прочитать»). Разовая стоимость < $2.

## 3. Адаптивный алгоритм (детерминированный, без AI)

Новый файл `src/lib/diagnostic/engine.ts` — чистые функции, юнит-тестируемые.

**Роутер (staircase):**
```
state = { level: A2 (старт), asked: [], correctStreak: 0, wrongStreak: 0 }
шаг: взять неиспользованный вопрос уровня state.level (ротация по seed)
  верно  → correctStreak++; wrongStreak=0; если correctStreak≥2 → level++ (max C1), streak=0
  неверно→ wrongStreak++;  correctStreak=0; если wrongStreak≥2 → level--, (min A1), streak=0
стоп: задано 12 вопросов ИЛИ (задано ≥8 И было ≥2 смены направления — уровень «зажат»)
выход L = уровень, на котором задано больше всего вопросов при точности ≥50%
     (тай-брейк: более низкий уровень — консервативно)
```
Самооценка из онбординга задаёт стартовый уровень лестницы (Beginner→A1, Basic→A2, Mid→B1, Advanced→B2, «не знаю»→A2) — экономит 2–3 вопроса.

**Навыковые блоки:** фиксированный уровень контента: Dinleme/Okuma берут блок уровня `clamp(L, A2, B2)` (ниже A2 аудирование/чтение бессмысленно мерить — честно ставим A2-блок; C1-кандидату даём B2-блок, C1 подтверждается только моками — отметить в UI).

**Скоринг секций (/25, честный):**
```
dinleme_25 = round(accuracy × 25)
okuma_25   = round(accuracy × 25)
yazma_25   = из AI-оценки (уже /25 в схеме writing_review)
konusma_25 = null (pending) → после первого урока = round(avg(report.criteria)/5 × 25)
total = сумма имеющихся; UI: «68/75 по трём секциям + Konuşma после первого урока»
Диапазон на результатах: [total−7, total+5] (7 ≈ 1 SE бинома на 26 вопросов ×25) —
формулу зафиксировать константами с комментарием, не «на глаз».
```
**Уровень CEFR общий** = уровень L из роутера, скорректированный: если (dinleme+okuma)/50 < 0.4 → L−1; если > 0.85 → без изменений (рост уровня только через роутер/моки). Карта пробелов = темы неверных ответов всех этапов (сущ. механика `AnswerRecord` + сев).

## 4. AI-проверки в диагностике

**Yazma:** переиспользовать ГОТОВЫЙ путь: `buildWritingReviewSystem` + `callAI(task: "diagnostic_analysis")` (маршрут DS-V4-Pro / KK→Sonnet уже настроен, fallback есть). Отличия от кабинетного Writing: промпт-задание из банка по уровню L; лимит — отдельная фича `diagnostic` в `consume_ai_quota` (2/день — анти-абьюз ретейков, конфиг в limits.ts). Результат пишется в `QuizResult.yazmaReview` (полная структура WritingReview) — на результатах показываем 2–3 главные ошибки + балл; ошибки уходят в сев (source `diagnostic`).
Эндпоинт: **новый** `POST /api/ai/diagnostic-writing` (копия /api/ai/writing с фичей `diagnostic` и без XP) — не смешивать квоты.
Анонимный проход: диагностика до регистрации → Yazma-проверку откладываем: текст сохраняется в `QuizResult.writingText` (localStorage), проверка запускается на `/quiz/result` ПОСЛЕ логина (там же, где сев). UI: секция Yazma в состоянии «проверяется…» ~1 мин.

**Konuşma:** v2 НЕ записывает аудио в квизе (решение из Р2 подтверждено): плейсмент = первый живой урок. Механика досчёта: `voice_sessions.report` уже содержит criteria/5 → при показе результатов, если `konusma_25 == null` и есть завершённая сессия — досчитать и обновить `profiles.quiz_result` (функция `attachKonusmaScore()` в engine.ts, вызов на дашборде/результатах). CTA на результатах: «Пройди первый урок — узнаешь балл Konuşma» → прямой линк на live.

## 6. Вопрос «сколько минут в день» (требование основателя)

Онбординг квиза, новый шаг после самооценки уровня: 4 карточки — **15 / 30 / 45 / 60+ мин** (лейблы «Лёгкий/Стабильный/Уверенный/Интенсив» + честный подзаголовок «влияет на длину дневного плана, можно менять в настройках»). Сохранение: в `QuizResult.minutesDaily` → на `/quiz/result` в `profiles.study_minutes_daily`. Существующий `IntensityModal` на дашборде: маппинг minutes→Intensity (15→light, 30→medium, 45|60→intensive) до планового движка; движок (DESIGN-PLAN-ENGINE §4) использует минуты напрямую и делает `Intensity` legacy. Редактирование в настройках — часть блока D/движка (см. Б-чертёж §6).

## 8. Риски и приёмка

| Риск | Митигация |
|---|---|
| Калибровка сложности вопросов «на глаз» → систематический сдвиг уровня | консервативные тай-брейки (вниз); после запуска собрать факт: `answers` уже пишутся — правим уровни вопросов по реальной статистике решаемости |
| Авторинг банка ~92 вопросов | процесс из Content-чертежа §4 (AI-драфт → нейтив-ревью); роутер критичнее всего — его 30 вопросов ревьюим в первую очередь |
| Аудио TTS звучит «синтетически» | multilingual_v2 + прослушивание основателем; честная пометка в UI не нужна (тренажёрная норма), но в маркетинге не называть «носителями» |
| Ретейк-фарм скидки/XP | XP-дедуп уже есть; скидка привязана к `diagnostic_completed_at` (не обновлять при ретейке — уже так); AI-проверка Yazma ограничена 2/день |
| Пользователь бросает на середине | существующий QuizProgress-механизм сохраняется поэтапно (router state сериализуем) |

**Приёмка:** (1) юнит-тесты engine.ts: лестница сходится за ≤12 шагов на синтетических профилях «чистый A2», «рваный B1», «всё верно», «всё неверно»; (2) прогон 5 живых персон (основатель + знакомые разных уровней) — уровень совпадает с ожиданием ±0.5 ступени; (3) карта пробелов содержит только темы реально неверных ответов; (4) сев виден в `topic_mastery` и влияет на фокус первого урока.
